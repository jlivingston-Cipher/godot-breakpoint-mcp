# Breakpoint MCP — the queue

> 🔴 **THIS FILE EXISTS BECAUSE THE QUEUE WAS THE ONE TABLE IN THIS REPOSITORY NOTHING
> READ.** Every counter a handoff prints is bound to the instrument that printed it and
> compared to the digit; `handoff_gate.py` refuses a status block over a single atom that
> does not bind. The section of the same document that says *what should happen next* was
> prose, in a file `.gitignore` keeps out of the tree, and no gate has ever opened it.
>
> The consequence is measurable and it was measured before this file was written. Across
> sessions 220–239 the Open section held **20–25 items and never drained**: generation and
> closure were equal, and what got closed was always the newest. Every session closed the
> two items the previous session had created and carried the rest. Measured ages at 239:
> the review charter's P0 had been open **34 sessions**, `D1b` 33, the
> `declared-outside-this-file` five 25, `prepack` 24. The typed ages disagreed with each
> other about their own convention — one row counted from the session that opened it,
> another from the session after — which is exactly the drift a reader catches and prose
> does not.
>
> **So the ages are not written here.** There is no column to type one into.
> `queue_gate.py` derives every age from `opened` and `QUEUE_HEAD`, and the strongest pin
> available on a number nobody rechecks turned out to be deleting the place it could be
> written.

## The table

`state` is one of `OPEN`, `SCHEDULED`, `DONE`, `KILLED`. `—` means not applicable.

`reach` is one of `user`, `internal`, and it is the **priority order, enforced**.

* `user` — an installer or operator of the shipped package can observe it: `host/src` and
  addon behaviour, CLI and error copy, packaging, `README.md`, `docs/USER_GUIDE.md`.
  **Subject to the ceiling and to the schedule check.**
* `internal` — everything else: gates, instruments, the handoff apparatus, CI,
  contributor tooling. Real work, none of it reaching a customer. **Deferred, with no
  clock** — no ceiling, no targets — because `QUEUE_TIER_ORDER` already forbids anyone to
  finish one while a `user` row is live, and a ceiling over work nobody is permitted to
  touch demands a decision every eight sessions about nothing. That is churn wearing
  governance.

`paths` is the **evidence for the `reach` cell beside it** — the tracked paths the row's
work touches, `;`-separated, `—` if undeclared. Added at 271.

🔴 **THE TIER WAS A PATH PREDICATE THAT EXISTED ONLY AS THE SENTENCE ABOVE.** 248 defined
`user` by the files a row's work touches, and then asked every session to apply that
sentence by hand and type the answer into a cell nothing read. 267 and 268 re-tiered five
rows `internal` → `user` between them and never once the other way; 268 read that as a
typing bias, 269 found that `QUEUE_TIER_ORDER` had made `user` the only answer that let a
session close its work. **Both readings were unfalsifiable, because there was nothing to
check the column against.** Now there is: `queue_gate.py` carries `REACH_PATHS`, an
ordered roster tiering each path with the reason it lands where it does; it derives the
row's tier from the row's own paths and refuses a disagreement. **Any path a user can
observe makes the row `user`** — one file an installer can see is enough — and every
declared path must be one this repository actually tracks, which is what makes this a join
to the tree rather than a second sentence agreeing with the first.

The column turns on at 271 rather than over the back catalogue: retro-fitting it to
ninety-six historical rows would be ninety-six guesses about what long-finished sessions
were touching, typed by somebody who was not there. A row opened or closed at 271 or later
must declare its paths; older rows carry `—` and are **counted, not excused** — the live
undeclared count is ceilinged at what it was when the column landed, so it can only fall.

🔴 **THE COLUMN WAS ADDED AT 248 AGAINST A MEASUREMENT, NOT A HUNCH.** Of the sixteen
live rows at 247, **zero** were observable by anyone who installs this package. Twenty-five
commits had landed since the `v1.74.0` tag — 15,664 insertions — and **exactly one touched
a file a user can reach.** The apparatus measuring this product had reached 36,987 lines
against the product's 20,885: **1.77×**.

That is not a queue whose priorities slipped. It is a queue with **no intake**. Every row
in it was generated by a session reading the previous session's output, because nothing
else was feeding it: 0 open issues and 0 open pull requests against ~3,700 downloads. A
loop with one input generates rows about itself, and it will do so indefinitely without
ever being wrong about anything.

🔴 **SO THE COLUMN IS HALF THE FIX AND THE SMALLER HALF.** Sorting an empty tier does
nothing. The rows that opened Tier 1 at 248 came from installing the published tarball and
running it the way `docs/USER_GUIDE.md` says to — which had never been done, and which
found four user-facing defects in the first few minutes. **An empty Tier 1 is a reading to
distrust before it is a reading to act on.**

* `OPEN` — no decision has been taken. **Subject to the ceiling**: `queue_gate.py` refuses
  an `OPEN` row older than `AGE_CEILING` sessions. The ceiling does not demand the work;
  it demands a decision, because an item nobody has picked up in twenty-five sessions is a
  decision not to do it that nobody wrote down.
* `SCHEDULED` — a `target` session is required, and **the target is checked**. A
  `SCHEDULED` row whose target has passed without becoming `DONE` or `KILLED` is refused.
  Without that half, `SCHEDULED` is just `OPEN` with the ceiling laundered off it.
* `DONE` / `KILLED` — a `closed` session is required, and `KILLED` requires a `why`.
  Closed rows **stay in the table**; they are the only record that the decision was taken,
  and `QUEUE_ROW_FLOOR` refuses a table that lost rows.

## What the gate refuses

| claim | refuses |
|---|---|
| `QUEUE_PARSE` | a row that does not parse, a duplicate or non-slug id, a session field that is not an integer, a table under `QUEUE_ROW_FLOOR` |
| `QUEUE_FIELDS` | a state missing the field it requires, or carrying one it must not — an `OPEN` row with a `closed` session is a contradiction, not a note |
| `QUEUE_AGE_DOMAIN` | a row whose `opened` or `closed` session is AFTER the head, or whose `closed` precedes its `opened` — the bounds the derived age is computed under, checked in `parse` so `--render` and `--ages` refuse them too. `target` is exempt: a schedule is a promise about a session that has not arrived, and `QUEUE_SCHEDULE_HONOURED` is the claim with an opinion about it |
| `QUEUE_REACH_JOIN` | a row whose declared `paths` derive a different tier from the `reach` typed beside them, a declared path this repository does not track, a path no `REACH_PATHS` row tiers, or a row opened or closed at 271 or later that declares none |
| `QUEUE_REACH_UNDECLARED` | more live rows carrying `—` for `paths` than the ceiling — the grandfathered back catalogue, counted rather than excused, on a number that can only fall |
| `QUEUE_AGE_CEILING` | an `OPEN` row older than `AGE_CEILING` sessions |
| `QUEUE_SCHEDULE_HONOURED` | a `SCHEDULED` row whose `target` has passed and which is still not closed |
| `QUEUE_TIER_ORDER` | a session that **finished** an `internal` row while any `user` row was still live. It governs closing and not opening, deliberately: refusing to let a session RECORD an internal finding would not defer the finding, it would lose it |
| `QUEUE_NOT_ONLY_NEWEST` | a session that closed **internal** items and **finished** none it did not itself create — a `KILLED` row does not answer it. Scoped to the internal tier at 248: the pathology is a session inventing gate work and closing its own invention, and a `user` row cannot be that, because the tier is defined by coming from outside |
